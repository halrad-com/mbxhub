# What each sample needs, and the command that builds it.
#
# Ten folders, four toolchains, and five with no build at all. Nothing here
# installs anything - this is the answer to "why won't this one build", read
# before you spend twenty minutes on it, and the command to run once it will.
#
# Every command below is written to run FROM THIS DIRECTORY (samples/).
#
# EVERY sample that talks to the hub needs a RUNNING MBXHub, which is MusicBee
# with the plugin loaded. The hub is not a package you install for a sample; it
# is the thing the sample integrates with. Default http://localhost:8080, and
# ports are claimed as an even pair, so a machine whose 8080 was taken is on
# 8082 - see MBXHUB-SDK/integration-guide.md, "Find the hub".
#
# Versions are what the sample DECLARES or was built against. A range is the
# sample's own floor, not a guess.


# ================================================================ .NET =======
# .NET SDK 8.0 or newer. NuGet restore happens as part of the build.

hello-app            net8.0-windows
                     Microsoft.Web.WebView2  1.0.4078.44
                     WINDOWS ONLY - the -windows target and WebView2 do not
                     travel. The other two .NET samples do.
  BUILD              dotnet build hello-app/hello-app.csproj -c Release
  RUN                dotnet run --project hello-app/hello-app.csproj

hello-charm          net8.0
  BUILD              dotnet build hello-charm/hello-charm.csproj -c Release
  RUN                dotnet run --project hello-charm/hello-charm.csproj

hello-endpoint       net8.0
  BUILD              dotnet build hello-endpoint/hello-endpoint.csproj -c Release
  RUN                dotnet run --project hello-endpoint/hello-endpoint.csproj


# ================================================================ C++ ========
# Visual Studio 2022 with the "Desktop development with C++" workload, which
# supplies both the MSVC toolset and the CMake the script uses. build.cmd finds
# it through vswhere - no PATH setup, no Developer Prompt.
#
# THE SIBLING CHECKOUT IS A BUILD DEPENDENCY, not an optional extra: the Spout2
# SDK sources and mbxspout.h come from ../../../mbxspout, so it must be cloned
# beside this repository -
#
#     source/repos/mbxhub/          <- you are here
#     source/repos/mbxspout/        <- must exist
#
# AT RUNTIME it loads mbxspout.dll, looked for beside the exe first and then in
# the sibling checkout's build\Release.
#
# build.cmd is also the WORKED EXAMPLE of wrapping a toolchain: discover it,
# fail with a named reason when it is absent, and put the output somewhere
# predictable. The .NET samples need no wrapper because dotnet already is one.

hello-spout          Visual Studio 2022  (Desktop development with C++)
                     CMake               (bundled with that workload)
                     mbxspout            sibling checkout - sources + header
                     mbxspout.dll        at runtime
  BUILD              hello-spout\build.cmd
  RUN (two windows)  hello-spout\build\Release\hello-spout.exe --send
                     hello-spout\build\Release\hello-spout.exe --dll <path>
